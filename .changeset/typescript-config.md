An opt-in `typescript` config, from `docs/catalog-typescript.md`, on the same JavaScript and TypeScript files as `recommended`: three report-only rules, `ts-no-definite-assignment-assertion` (a `let x!: T` or a class field `name!: T`), `ts-no-amd-dependency` (a `/// <amd-dependency />` directive) and `ts-no-module-augmentation` (a `declare module "…"` in a module), and ESLint's `eqeqeq` set to `"always"`, so `value == null` is reported too. It needs nothing that `recommended` does not. And two companions: `typescript-extended`, which adds `@typescript-eslint/no-explicit-any`, `@typescript-eslint/consistent-type-assertions` (`assertionStyle: "never"`), `@typescript-eslint/no-non-null-assertion` and `@typescript-eslint/triple-slash-reference` (`path: "never"`, `types: "prefer-import"`, `lib: "never"`) on TypeScript files and `promise/prefer-catch` on every file, listed one by one; and `typescript-extended-type-checked`, which adds `@typescript-eslint/no-floating-promises` and `@typescript-eslint/switch-exhaustiveness-check` with the project service on. ESLint gets `configs.typescript`, `configs["typescript-extended"]` and `configs["typescript-extended-type-checked"]`; Oxlint the `typescript` and `typescriptExtended` exports of `eslint-plugin-clean-code-book/oxlint`, where `typescriptExtended` runs Oxlint's native `typescript` and `promise` plugins and loads no JS plugin. The type-checked config has no Oxlint export. `eslint-plugin-promise` (7.2 or later) is a new optional peer dependency, needed only by ESLint's two extended configs. The repository's decisions are now recorded in `docs/adr/`. `recommended`, `recommended-type-checked`, `ai`, `node`, `node-extended`, `react` and `react-extended` are unchanged.
