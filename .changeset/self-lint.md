The plugin now lints itself with its own `recommended-type-checked`, `typescript` and `ai` configs, and three rule bugs that run found are fixed. `no-noise-words` reports the word `variable` only at the end of a name after another word (`nameVariable`), not alone or inside a longer name (`variable`, `variableWord`, `VARIABLE_DEFS`), where it names the thing itself, as Use Solution Domain Names allows. `no-position-markers` leaves a run inside a Markdown code span of a doc comment alone, since it quotes code; its autofix had stripped such an example. `stepdown-order` checks a function's own name, not its last parameter, before moving it, so it no longer moves a function with parameters that a `var` of the same name also declares. The message ids of `ai-no-placeholder-values` and `ai-no-placeholder-implementation` are now `placeholderValue` and `stubImplementation`.

`ai-no-inline-comments` also reports a `/** */` doc comment that documents nothing: one on a statement, with nothing after it, or inside a function body, even on a local declaration. A doc comment still stays on a declaration outside any function body, and as the file's overview before the first statement. Before, any comment written as `/** */` passed, so a narrating comment could pass for documentation.

A new opt-in `jsdoc` config checks that doc comments are well-formed, from *Clean Code*'s warning that "Document comments can be just as misleading, nonlocal, and dishonest as any other kind of comment" ([`docs/catalog-jsdoc.md`](docs/catalog-jsdoc.md)). It turns on `eslint-plugin-jsdoc`'s `check-param-names`, `check-tag-names` and `empty-tags` on JavaScript and TypeScript files, and `no-types` on TypeScript files only, each an `error`, listed one by one. `eslint-plugin-jsdoc` is a new optional peer dependency, loaded only when `jsdoc` is read. Oxlint's `jsdoc` export runs `check-tag-names` and `empty-tags` natively and loads no JS plugin; `check-param-names` and `no-types` are ESLint only. The plugin also lints itself with `jsdoc`.

`jsdoc` also turns on a rule of this plugin, `jsdoc-names-every-parameter` (DOC-05), on JavaScript and TypeScript files, under ESLint and under Oxlint, which loads it through `jsPlugins`. It reports a function whose `/** */` doc comment skips a parameter: each parameter must be named in the comment as a code span, such as `` `first` ``, or by an `@param` tag with a description. A parameter whose name starts with `_`, TypeScript's `this`, and a function with no doc comment are not reported; a destructured parameter is named when each name it binds is, or by one `@param` for the whole pattern. It has no autofix. The plugin's own doc comments now name every parameter.
